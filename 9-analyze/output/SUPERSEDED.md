## Superseded *sections* of current files

`rule_default_evidence.csv` is written by `stress_rule_comparison.R` and is
**current in date but superseded in method**. It reports the raw
initial-vs-non-initial contrast in all-reduced polysyllables, which is
confounded by final lengthening: in a disyllable "non-initial" is the final
syllable, and the final syllable of an utterance-final word runs +69%
(`final_lengthening_models.csv`). Use `default_adjudication.csv`, which fits
the same contrast with word-final position, utterance-final position and
position-within-utterance in the model. The two disagree in sign on duration.

The `final` and `initial` rows of `master_rule_comparison.csv`'s
`dAIC_log_duration` column are uninterpretable for the same reason — the
`final` rule's predictor *is* the confound, and it wins that column by
ΔAIC 17,013 over the best named rule. The six named rules' relative ranking is
unaffected.

## 2026-09-27 — aligner symbol ⟨ӗ⟩ mismapped in the Python phone table

`7-extract/reextract/build_phone_table.py` mapped the aligner's `ɛ` to the
config's `e` instead of `ø`. The MFA dictionary writes ⟨ӗ⟩ (the reduced front
vowel, this config's /ø/) as `ɛ` and ⟨е⟩ as `e`; stage 5 confirms the split by
classing `ɛ` as WEAK and `e` as STRONG. The effect was that /ø/ was absent from
`phones_chuvash_voice.csv` altogether, /e/ pooled ⟨е⟩ with ⟨ӗ⟩, and every ⟨ӗ⟩
token silently entered the **full**-vowel class.

The R pipeline was never affected — it reads 6-annotate labels through
`ALIGNER_IPA_TO_CONFIG`, which is correct — so the coda/sonority, adjudication,
final-lengthening, rule-ranking, vowel-space and positional results stand
unchanged. Two Python-side results were wrong and have been recomputed:

**Word-final weight, adjusted 2×2** (`gemination_weight_model.csv`).
Superseded → current, as % of the reference cell (short C + full V) and as the
model's fitted rhyme duration:

| cell | superseded | current | fitted ms |
|---|---|---|---|
| short C + full V | 0.0% | 0.0% | 195.7 |
| long C + full V | +19.4% | +19.3% | 233.5 |
| short C + reduced V | −12.1% | −7.1% | 181.8 |
| long C + reduced V | +4.6% | +11.2% | 217.7 |

The interaction is still additive (β +0.0032, t 0.30). **The earlier gloss was
wrong and must not be reused**: it said a long consonant plus a reduced vowel is
indistinguishable from a short consonant plus a full vowel (~7 ms, under the
10 ms JND). On the corrected data that comparison is 217.7 vs 195.7 ms, a
**+22 ms** difference, above the JND. Correct statement: consonant length and
vowel class contribute independently to rhyme duration, with no sign of
compensation between them — which is itself evidence against a fixed-weight
moraic rhyme, since a zero-mora reduced vowel plus a mora-adding long consonant
should have traded off.

**Mora / fleeting-vowel test** (`mora_evidence.csv`). Now 37,970 tokens in
3,857 word types (was 10,992 in 964), because ⟨ӗ⟩-final words had been excluded
by the mismapping. The null is unchanged and better powered: alternating vs
non-alternating gives final vowel β −0.0158 (t −1.17), rhyme −0.0053 (t −0.48),
final consonant +0.0257 (t +1.78). The morphological confound documented in
`minimal_word_diagnosis.md` still applies and is still the reason this corpus
cannot settle the question.

## 2026-09-27 (later) — "word-final geminate" was the wrong description

`gemination_mora.R` block 3 joins the consonant at `pidx - 1` to the word-final
vowel, so the measured unit is the **final CV sequence** and a long consonant in
it is **intervocalic** (пул-ли), not word-final. Two things were mislabelled:

- The unit was called a **rhyme**. It is not: in пул.ли the consonant belongs to
  the preceding syllable. `median_rhyme` is now `median_final_CV`.
- `c_long` was described as a **word-final geminate**. It is the geminate of
  пулли, which is prevocalic.

The numbers are unchanged and the comparison is a good one — it is exactly the
пулӑ ~ пулли contrast — but it must be described as the final CV sequence:
C+full 195.7 ms, Cː+full 233.5, C+reduced 181.8, Cː+reduced 217.7.

**The corpus cannot address word-final geminates.** Chuvash Voice has 61
word-final long-consonant tokens in 22 word types, almost all Russian loans
(класс, пресс, стресс, Кирилл, кристалл) plus onomatopoeia and line-break
truncations. The orthography agrees: word-final geminates are 1.2% of
monolingual types and 0.050% of tokens, against 85.3% intervocalic. Any claim
about the phonetics of word-final geminates in Chuvash is therefore out of
reach here, and the earlier framing of the 2×2 as a word-final weight result
should not be reused.

## 2026-09-28 — geminating_stems.py superseded by geminating_stems.R

The Python version reads `/tmp/mono_all_types.csv`, a scratch export, and uses
a hand-written homoglyph map. The R port reads `mono_clean.rds` through the
config's `normalise_orthography()`, which is the pipeline's own path. Counts
differ: 406,973 usable monolingual types against 412,484 raw rows. Two separate
counts, which an earlier version of this entry conflated:

- **confirmed members** (bare form attested, in the wordlist, reduced vowel
  stem-final, geminate attested ≥ 10 times): **R 65, Python 62**. The R set is
  a superset — all 62 plus качӑ (каччӑ), тӑрӑ and ҫӳлӗ.
- **wordlist CFCR/CRCR types whose reduced vowel is stem-final**, from the
  control table: **R 66, Python 63**. Every one of them geminates in both runs.

`geminate_freq_total` differs on 46% of shared roots because the source
frequency tables differ. **Use the R version.** Any earlier number quoted from
the Python run should be re-read from `output/geminating_stems.csv` as
regenerated by `geminating_stems.R`.

The headline result is unchanged and marginally stronger: of the 173 wordlist
CFCR/CRCR types ending in a reduced vowel, **66 have a stem-final reduced vowel
and all 66 geminate; none do not.** (The Python run gave 63 of 173, likewise
with none failing to geminate.)
